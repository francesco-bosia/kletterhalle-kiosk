# Persistent Kiosk via systemd — Design

**Date:** 2026-06-11
**Status:** Approved (pending spec review)

## Problem

On the Raspberry Pi, the operator currently SSHes in, pulls the latest code,
runs `npm run build`, `npm run start`, and then `kiosk.sh` by hand. When the SSH
session ends, the shell sends `SIGHUP` and both the Next.js server and the
Firefox kiosk are killed. The kiosk therefore only stays up while a remote
session is open.

**Root cause:** processes launched in an interactive SSH session are children of
that session and die with it. The fix is to hand both processes to systemd so
they are owned by long-lived service managers instead of the login session.

## Goals

1. **Unattended server on boot.** The Next.js app starts automatically when the
   Pi powers on, with no login or SSH required, and restarts if it crashes.
2. **Survive disconnect.** Neither the server nor the browser dies when the
   operator logs out of SSH.
3. **Simple updates.** Pulling new code and restarting is a single script that
   can be run over SSH and left to run after disconnect.

## Constraints / Decisions

- **Repo path on the Pi:** `~/Documents/kletterhalle-kiosk/`.
- **Login user:** the Pi's desktop login user (referred to below as
  `<pi-user>`; substitute the real username, e.g. `pi`). System-service files
  must use this user and the absolute repo path.
- **Password is kept** on the desktop (no passwordless auto-login). Consequence:
  the browser cannot appear on a bare power cycle until someone logs in
  physically at the screen once. The **server** still auto-starts regardless.
  After that single physical login, the kiosk is self-sustaining and survives
  all SSH disconnects.
- **Browser/display target:** Firefox on Wayland (matches the current
  `scripts/kiosk.sh`, which works today). The Chromium/X11 variant generated by
  `setup-pi.sh` is stale and will be removed.

## Architecture

Two systemd services with complementary scopes:

| Concern | Unit | Scope | Starts on | Survives SSH logout |
|---------|------|-------|-----------|---------------------|
| Next.js server (`npm start`) | `kletterhalle.service` | system | boot (`multi-user.target`) | yes |
| Firefox kiosk (`kiosk.sh`)   | `kiosk-browser.service` | user | physical desktop login (`graphical-session.target`) | yes |

The two are **not** hard-linked. `kiosk.sh` already polls
`http://127.0.0.1:3000` with `curl` until the server responds, so the browser
self-synchronizes with the server. (A user service also cannot cleanly
`Requires=` a system service, so this is the correct decoupling.)

## Components

### 1. `kletterhalle.service` (system service)

Existing file, corrected for user/path. Installed to
`/etc/systemd/system/kletterhalle.service`.

```ini
[Unit]
Description=Kletterhalle Next.js App
After=network.target

[Service]
Type=simple
User=<pi-user>
WorkingDirectory=/home/<pi-user>/Documents/kletterhalle-kiosk
ExecStart=/usr/bin/npm start
Restart=always
RestartSec=10
Environment=NODE_ENV=production

[Install]
WantedBy=multi-user.target
```

Enabled once with `sudo systemctl enable --now kletterhalle.service`.

### 2. `kiosk-browser.service` (user service)

Installed to `~/.config/systemd/user/kiosk-browser.service`. Replaces the
committed X11/`DISPLAY=:0` version.

```ini
[Unit]
Description=Kletterhalle Kiosk Browser
After=graphical-session.target
PartOf=graphical-session.target

[Service]
Type=simple
ExecStart=%h/Documents/kletterhalle-kiosk/scripts/kiosk.sh
Restart=always
RestartSec=5

[Install]
WantedBy=graphical-session.target
```

- `%h` resolves to the user's home, so the unit is username-agnostic.
- `ExecStart` points at the **repo copy** of `kiosk.sh`, so `git pull` updates
  the launch logic — no copying to `~/kiosk`.
- Enabled once with `systemctl --user enable kiosk-browser.service`.
- Logs: `journalctl --user -u kiosk-browser`.

`scripts/kiosk.sh` is unchanged — it already defensively exports
`XDG_RUNTIME_DIR`, `WAYLAND_DISPLAY`, and `MOZ_ENABLE_WAYLAND`, which is exactly
what a systemd-user launch needs.

### 3. `scripts/deploy.sh` (new)

The update workflow, run over SSH. Both restarts hand processes to systemd, so
the operator can disconnect immediately afterward.

```bash
#!/bin/bash
set -euo pipefail

cd ~/Documents/kletterhalle-kiosk
git pull
npm ci
npm run build
sudo systemctl restart kletterhalle          # server (system service)
systemctl --user restart kiosk-browser        # browser (user service)

echo "Deploy complete. Safe to disconnect — services keep running."
```

### 4. `scripts/setup-pi.sh` (edits)

- **Remove** the heredoc that generates the Chromium/X11 `~/kiosk/kiosk.sh`.
- **Remove** the `~/.config/autostart/kiosk.desktop` autostart entry.
- **Keep** installing `kletterhalle.service` (correct the user/path to the
  `Documents` path).
- **Add** installation + enable of the user service:
  ```bash
  mkdir -p ~/.config/systemd/user
  cp ~/Documents/kletterhalle-kiosk/scripts/kiosk-browser.service \
     ~/.config/systemd/user/kiosk-browser.service
  systemctl --user daemon-reload
  systemctl --user enable kiosk-browser.service
  ```
- **Document** in the final "Next steps" output: on first boot, log in once at
  the physical screen; thereafter server and kiosk are self-sustaining.
- `loginctl enable-linger` is intentionally **not** used — the browser requires
  the live graphical session, so lingering would not help it start any earlier.

## Files changed

- `scripts/kletterhalle.service` — correct `User=`/`WorkingDirectory=` to the
  `Documents` path.
- `scripts/kiosk-browser.service` — rewrite from X11 system-service form to the
  Wayland user-service form above.
- `scripts/deploy.sh` — new.
- `scripts/setup-pi.sh` — remove Chromium/autostart blocks, add user-service
  install, update docs.
- `scripts/kiosk.sh` — unchanged.

## Testing / Verification

Performed on the Pi (manual, since this is host/display-dependent):

1. `sudo systemctl enable --now kletterhalle.service` → `curl http://127.0.0.1:3000`
   returns the app. Reboot → app responds before any login.
2. `systemctl --user enable kiosk-browser.service`, log in at the physical
   screen → Firefox opens in kiosk mode on the attached display.
3. Kill Firefox → it relaunches within ~5s (`Restart=always`).
4. SSH in, run `scripts/deploy.sh`, disconnect → both services remain up; the
   kiosk reflects the new build.
5. `journalctl --user -u kiosk-browser` and `journalctl -u kletterhalle` show
   service logs.

## Out of scope

- Passwordless auto-login (explicitly declined).
- Migrating off Firefox/Wayland.
- Unrelated refactors of `setup-pi.sh` beyond the kiosk-launch path.
